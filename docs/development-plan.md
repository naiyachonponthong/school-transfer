## 🧱 Phase A — ฐานราก (ทำก่อนทุกอย่าง)

แต่ละข้อย่อยส่งแยกได้ ไม่กระทบหน้าจอเดิม

### A1 ประวัติชั้นเรียน (`enrollments`) ✅ ทำแล้ว (ยกเว้นย้ายห้องกลางปีและคละห้อง)
- ตารางใหม่ `enrollments`: นักเรียน × ปีการศึกษา × ห้อง × เลขที่ × สถานะ (กำลังเรียน/เลื่อนชั้น/ซ้ำชั้น/ย้ายออก/จบ)
- `students.classroom_id` เก็บไว้เป็น "ห้องปัจจุบัน" query เดิมทั้งหมดจึงยังใช้ได้ ส่วนข้อมูลย้อนหลังอ่านจาก `enrollments`
- Migration เติมข้อมูลย้อนหลัง: ปีปัจจุบันจาก `students.classroom_id` ปีก่อนหน้าจาก `attendances.classroom_id` และ `courses.classroom_id` ของคะแนนที่มี
- แก้ `gradesFor()`, สมุดพก, หน้าผู้ปกครอง, หน้านักเรียน, ปพ.1 ให้หาห้องจาก enrollment ของปีนั้น
- เลื่อนชั้นใหม่: หน้าตรวจสอบก่อนยืนยัน, ติ๊กคนซ้ำชั้น, จัดห้องใหม่/คละห้อง, ปุ่มยกเลิกการเลื่อนชั้นครั้งล่าสุด
- ย้ายห้องกลางปี: ปิด enrollment เดิม เปิดใหม่ คะแนนเดิมตามไปด้วย

### A2 กันข้อมูลหายจากการลบ ✅ ทำแล้ว
- เปลี่ยน FK `invoices.student_id`, `payments.invoice_id`, `payment_slips.invoice_id` เป็น `restrictOnDelete`
- นักเรียนที่มีประวัติ (การเงิน/คะแนน/เช็คชื่อ) ลบไม่ได้ ให้เปลี่ยนสถานะแทน
- ผู้ใช้ที่มีประวัติ กดลบ = ปิดใช้งาน · รายวิชาที่มีคะแนนลบไม่ได้ · ห้องที่มีประวัติชั้นเรียนลบไม่ได้
- ไม่ได้ใช้ `SoftDeletes` ตามร่างแรก: แถวที่ซ่อนอยู่ทำให้ `student_code`/`username` ซ้ำไม่ได้แบบมองไม่เห็น และต้องแก้ relation เกือบทุก model การห้ามลบได้ผลเท่ากันโดยไม่มีผลข้างเคียงนี้

### A3 สิทธิ์ตามตำแหน่งงาน ✅ ทำแล้ว (ระดับโมดูล)
- `roles` (ชื่อ + รายการสิทธิ์) และ `role_user` บุคลากรหนึ่งคนถือได้หลายตำแหน่ง · `admin` ได้ทุกสิทธิ์ · ยังไม่กำหนดตำแหน่ง = สิทธิ์ของ "ครู"
- สิทธิ์ 13 ข้อ นิยามที่ `app/Support/Permissions.php` ตำแหน่งตั้งต้น 7 ตำแหน่ง: ครู, ผู้บริหาร, วิชาการ/ทะเบียน, การเงิน, พยาบาล, บรรณารักษ์, ธุรการ
- หน้า `/roles` เป็นตารางติ๊ก ตำแหน่ง × สิทธิ์ เพิ่มตำแหน่งเองได้ · กำหนดตำแหน่งที่หน้าแก้ไขผู้ใช้
- route ใช้ `permission:` แทน `role:admin` เมนูและกระดิ่งกรองตามสิทธิ์
- **พฤติกรรมที่เปลี่ยน**: ครูทั่วไปไม่เห็นใบแจ้งหนี้/ยอดการเงินอีกแล้ว ต้องได้ตำแหน่ง "การเงิน" หรือ "ผู้บริหาร"
- ⬜ ขอบเขตข้อมูลรายห้อง (ครูเห็นเลขบัตร/ที่อยู่/สุขภาพ เฉพาะนักเรียนห้องตัวเอง) และสิทธิ์แยก ดู/เพิ่ม/แก้/ลบ ต่อเมนู
- ⬜ จุดที่ยังใช้ `isAdmin()` ในความหมาย "เห็นทุกห้อง/ทุกวิชา" (ข้อสอบ การบ้าน ใบลา ประกาศ) ยังผูกกับผู้ดูแลระบบ

### A4 Audit log ✅ ทำแล้ว
- `activity_logs`: ใคร ทำอะไร กับอะไร ค่าเดิม→ค่าใหม่ IP เวลา · หน้า `/activity-logs` ค้นตามประเภท ผู้ใช้ ช่วงวันที่ คำค้น (สิทธิ์ `audit.view`)
- Trait `LogsActivity` ติดที่ Score, Assessment, Course, Invoice, Payment, Student, User, Role, BehaviorRecord · บันทึกการเข้าระบบ การเปลี่ยนตำแหน่ง และการแก้ตั้งค่า (ค่าความลับเก็บเป็น `***`)
- บันทึกเฉพาะเมื่อมีผู้ใช้ล็อกอิน (seed/คำสั่ง artisan ไม่ถูกบันทึก) · รหัสผ่านไม่ถูกเก็บ
- ลิงก์ "ประวัติการแก้ไข" ในหน้าใบแจ้งหนี้
- ⬜ บันทึกการ "เปิดดู" ข้อมูลอ่อนไหว · ลิงก์ประวัติในสมุดคะแนน · การลบข้อมูลเก่าตามอายุ

### A5 ความปลอดภัยบัญชีและไฟล์ ✅ ทำแล้ว (ยกเว้น 2 ข้อท้าย)
- `users.must_change_password` + middleware บังคับตั้งรหัสใหม่ (ขั้นต่ำ 8 ตัว) สำหรับบัญชีที่สร้าง/รีเซ็ตโดยเจ้าหน้าที่ และผู้ปกครองเดิมที่ยังใช้ 6 หลักท้ายเบอร์โทร (ตรวจตอนล็อกอิน)
- ล็อกบัญชี 15 นาทีเมื่อใส่รหัสผิด 5 ครั้ง นับตามชื่อผู้ใช้
- รหัสเชื่อม LINE หมดอายุ 10 นาที เดาผิด 5 ครั้งต่อ LINE user ถูกพัก 1 ชั่วโมง
- `line_channel_token`, `line_channel_secret` เข้ารหัสในฐานข้อมูล (ค่าเดิมยังอ่านได้ จะถูกเข้ารหัสเมื่อบันทึกหน้าตั้งค่าครั้งถัดไป)
- สลิป, ใบรับรองแพทย์, ไฟล์ลาครู, รูปแชท, งานที่ส่ง เก็บในดิสก์ `local` เปิดผ่าน `/files/{type}/{id}` ที่ตรวจสิทธิ์ · ไฟล์เก่าย้ายด้วย `php artisan files:privatize`
- ⬜ ลืมรหัสผ่านผ่าน LINE (ตอนนี้ยังต้องให้ผู้ดูแลรีเซ็ต)
- ⬜ 2FA สำหรับ admin/การเงิน

### A6 ความถูกต้องของการเงิน ✅ ทำแล้ว
- `document_sequences` + `lockForUpdate()` สำหรับเลขใบแจ้งหนี้ ใบเสร็จ ใบสมัคร ใบเสร็จค่าสมัคร (นับต่อจากเลขเดิม)
- ยกเลิกใบเสร็จพร้อมเหตุผล แถวและเลขที่เก็บไว้ ใบเสร็จพิมพ์มีคำว่า "ยกเลิก" ยอดรวมทุกหน้าไม่นับใบที่ยกเลิก

- **E1 ทะเบียนบุคลากร** ✅ `staff_profiles` (เลขบัตร วันเกิด วิทยฐานะ วันบรรจุ วุฒิ ใบอนุญาตประกอบวิชาชีพ ที่อยู่ ผู้ติดต่อฉุกเฉิน) + `staff_trainings` (หัวข้อ หน่วยงาน ชั่วโมง เกียรติบัตร) · เจ้าตัวแก้ของตัวเองได้ที่เมนู "ประวัติของฉัน" · ฝ่ายบุคคล (`staff.manage`) เห็นทะเบียนรวม อายุงาน ชั่วโมงอบรมรายปี · คำสั่ง `staff:license-remind` เตือนเจ้าตัวและฝ่ายบุคคลเมื่อใบอนุญาตเหลือ 90/30/7 วัน (ตั้งเวลาไว้ทุกวัน 08:30) · ⬜ รายงานลงเวลา/ลารายเดือนต่อคน, ส่งออกทะเบียน
- **E2 สารบรรณ** ✅ หน้า `/office`: หนังสือรับ / ส่ง / คำสั่ง / บันทึกข้อความ เลขทะเบียนรันแยกประเภทต่อปี แนบไฟล์ (ดิสก์ส่วนตัว) เวียนให้บุคลากรรายคนหรือทุกคน กดรับทราบ ดูว่าใครยังไม่รับทราบ แจ้งทาง LINE · ผู้รับเห็นเฉพาะฉบับที่เวียนถึงตัวเอง · ⬜ ขั้นตอนเสนอ-สั่งการ-ลงนาม, แก้ไข/ยกเลิกหนังสือ
- **E3 แจ้งซ่อมและจองทรัพยากร** ✅ หน้า `/repairs`: บุคลากรแจ้งพร้อมรูป ผู้ดูแลอัปเดตสถานะ/ผู้รับผิดชอบ/ผล แจ้งกลับผู้แจ้งทาง LINE · หน้า `/bookings`: จองห้อง/รถ/อุปกรณ์ ตามวันและช่วงเวลา กันจองซ้อน ผู้จองหรือผู้ดูแลยกเลิกได้ · ⬜ จองซ้ำรายสัปดาห์, ขั้นอนุมัติการจอง (ตอนนี้จองได้ทันที)

## 📊 Phase F — ผู้บริหารและประสบการณ์ใช้งาน (ทำแล้ว F1, F4 · ยังไม่ทำ F2, F3)

- **F1 แดชบอร์ดผู้บริหาร** ✅ หน้า `/executive` (สิทธิ์ใหม่ `executive.view` ตำแหน่งผู้บริหารได้โดยค่าเริ่มต้น): อัตรามาเรียน 8 สัปดาห์, มาเรียน 30 วันแยกระดับชั้น, เก็บค่าธรรมเนียมเทียบยอดที่ออก, ค้างชำระ/เลยกำหนด, การกระจายผลการเรียนและเกรดเฉลี่ยรวม, บุคลากรวันนี้, จำนวนนักเรียนที่มีสัญญาณเตือนและกรณีที่ดูแลอยู่ พิมพ์ได้ · ⬜ GPA แยกกลุ่มสาระ, เปรียบเทียบรายห้อง, รายงานประจำเดือนแบบเลือกเดือน
- **F2 PWA เต็มรูป / Web Push** ⬜ ยังไม่ทำ: ต้องเซ็น VAPID และเข้ารหัส payload ซึ่งควรใช้ package (`minishlink/web-push`) และทดสอบได้เฉพาะบน https จริง
- **F3 LINE Login / LIFF** ⬜ ยังไม่ทำ: ต้องมี LINE Login channel ของโรงเรียนและโดเมน https
- **F4 PDPA** ✅
  - ประกาศความเป็นส่วนตัว: ตั้งข้อความที่หน้าตั้งค่า ผู้ใช้ทุกคนต้องกดรับทราบก่อนเข้าใช้งาน (เก็บผู้ใช้ ฉบับ เวลา IP ใน `privacy_consents`) ขึ้นฉบับใหม่ได้ให้ทุกคนรับทราบซ้ำ · เว้นว่าง = ไม่บังคับ
  - ส่งออกข้อมูลส่วนบุคคลของนักเรียนรายคนเป็น JSON (สิทธิ์ `users.manage`) การส่งออกถูกลงประวัติการใช้งาน
  - คำสั่ง `privacy:purge` ลบใบสมัครที่ไม่มอบตัว ภาพสแกนข้อสอบ และประวัติการใช้งานที่พ้นระยะเก็บ มี `--dry-run` · **ไม่ได้ตั้งเวลาให้รันเอง**
  - ⬜ บันทึกความยินยอมแยกวัตถุประสงค์ (เช่น เผยแพร่รูป), ลบข้อมูลนักเรียนที่จบ/ย้ายออกเกินระยะเก็บ
- **F5 แชท** — ตรวจแล้วของเดิมหยุด poll เมื่อแท็บไม่ได้เปิดอยู่แล้ว (ผลตรวจรอบแรกของผมผิด) · ⬜ ยืดรอบเมื่อเงียบ

## ⚠️ ข้อควรระวัง

1. **Migration A1 ต้องเติมข้อมูลย้อนหลังให้ถูก** ทดสอบกับสำเนาฐานข้อมูลจริงก่อน และสำรองก่อนรันทุกครั้ง
2. **เงินใช้ DECIMAL** ตอนนี้ model cast เป็น `float` ควรเปลี่ยนเป็น `decimal:2` พร้อมกับ A6
3. **ห้ามลบข้อมูลการเงินจริง** ใบเสร็จใช้ยกเลิก (void) เท่านั้น เลขที่ต้องไม่ถูกใช้ซ้ำ
4. **`lockForUpdate()` ไม่มีผลบน SQLite** เทสต์เรื่องเลขเอกสารต้องรันบน MySQL
5. **โควตาข้อความ LINE OA** push/multicast นับตามจำนวนผู้รับ สแกนเข้า-ออกทุกวันทั้งโรงเรียนใช้ข้อความเยอะมาก ตรวจแพ็กเกจปัจจุบันของ LINE ก่อนเปิดทุกประเภทแจ้งเตือน และใช้ Web Push (F2) เป็นช่องหลักได้
6. **ปพ.1 และ ปพ.3 เป็นแบบพิมพ์ควบคุม** ระบบพิมพ์ลงแบบได้ แต่รูปแบบต้องตรงกับที่ต้นสังกัดกำหนด ต้องขอตัวอย่างจริงจากโรงเรียน
7. **PDPA** ข้อมูลสุขภาพ ผลคัดกรอง case ดูแลช่วยเหลือ เป็นข้อมูลอ่อนไหว ต้องจำกัดสิทธิ์และมี audit log (A3, A4) ก่อนเปิด Phase D
8. **HTTPS และ queue worker** A7 ต้องมี process รันคิว (Supervisor บน Linux, NSSM/Task Scheduler บน Windows) เพิ่มใน README
9. **ย้ายไฟล์ไป private (A5)** ลิงก์รูปเดิมในแชท/ฟีดจะเปลี่ยน ต้องแก้ view ที่อ้าง `asset('storage/...')` ให้ครบ
10. **เปลี่ยนสิทธิ์ (A3)** เขียนเทสต์ครอบทุกบทบาทก่อนสลับ middleware ของเดิมมี `SchoolSmokeTest` เป็นฐาน
