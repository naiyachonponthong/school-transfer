# ระบบบริหารโรงเรียน

ระบบบริหารงานโรงเรียนครบวงจร (แนวเดียวกับ School Bright) ที่เน้น **ใช้ง่าย ทำงานเสร็จเร็ว และใช้บนมือถือได้**
Laravel 13 + Blade + Bootstrap 5 ไม่ต้อง build frontend (ไม่ต้องใช้ npm)

## ทดลองใช้งาน

**ต้องใช้ PHP 8.3 ขึ้นไป** (Laravel 13) และ Composer — ถ้า `composer install` แจ้งว่า `requires php >=8.3` ให้เปลี่ยนเวอร์ชัน PHP ก่อน (Laragon: คลิกขวา → PHP → Version แล้วเปิด Terminal ใหม่ ตรวจด้วย `php -v`) · ส่วนขยายที่ต้องเปิดใน `php.ini`: curl, fileinfo, gd, mbstring, openssl, pdo_mysql (หรือ pdo_sqlite), zip

```bash
composer install
copy .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

เปิด http://127.0.0.1:8000

| บทบาท | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลระบบ / ฝ่ายวิชาการ | `admin` | `admin1234` |
| ครูประจำชั้น ม.1/1 (สอนคณิต) | `teacher` | `teacher1234` |
| ผู้ปกครอง (มีลูก 2 คน) | `0812345678` | `345678` |
| นักเรียน ม.1/1 (ลูกของผู้ปกครองตัวอย่าง) | `69001` | `student1234` |

ข้อมูลตัวอย่าง: 4 ห้อง, นักเรียน 102 คน, ครู 9 คน, เช็คชื่อย้อนหลัง 15 วัน, คะแนน, ตารางเรียน, ใบแจ้งหนี้ ฯลฯ

> **ก่อนใช้จริง** อย่าใช้ข้อมูลตัวอย่างนี้ ให้รัน `php artisan school:install` แทน (ดูหัวข้อ [เตรียมใช้งานจริง](#เตรียมใช้งานจริง-production-checklist) ด้านล่าง)

### ใช้ MySQL (Laragon)

แก้ `.env`:

```
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=school
DB_USERNAME=root
DB_PASSWORD=
```

สร้างฐานข้อมูล `school` (utf8mb4) แล้วรัน `php artisan migrate --seed`

## เตรียมใช้งานจริง (Production checklist)

ข้อมูลตัวอย่างจาก `--seed` มีไว้สำหรับทดลอง/สาธิตเท่านั้น ก่อนให้โรงเรียนใช้งานจริงให้ทำตามนี้:

1. **ฐานข้อมูล**: สร้างฐานข้อมูล MySQL แยกต่างหาก (utf8mb4) แล้วแก้ `.env` ตามหัวข้อด้านบน — **ห้ามใช้ SQLite กับงานจริง** (รองรับผู้ใช้พร้อมกันได้จำกัดกว่ามาก)
2. **ติดตั้งแบบสะอาด**: รันคำสั่งเดียวแทนการรัน `migrate --seed`:
   ```bash
   php artisan school:install
   ```
   คำสั่งนี้จะ **ล้างฐานข้อมูลทั้งหมด** สร้างตารางใหม่ และสร้างบัญชีผู้ดูแลระบบคนแรกให้ (ถามชื่อโรงเรียน/ชื่อผู้ใช้/รหัสผ่าน) **ไม่มีข้อมูลตัวอย่างติดมาด้วย** — เปลี่ยนรหัสผ่านทันทีหลังเข้าระบบครั้งแรก
   ใช้แบบไม่โต้ตอบ (เช่นใน CI/CD) ได้ด้วย `--force --name=... --admin-user=... --admin-password=...`
3. **ตัวแปรใน `.env`**:
   ```
   APP_ENV=production
   APP_DEBUG=false
   APP_URL=https://โดเมนของโรงเรียน
   ```
   เมื่อ `APP_ENV=production` ระบบจะบังคับ https ทุกลิงก์และตั้งคุกกี้เซสชันแบบ secure ให้เองอัตโนมัติ ([AppServiceProvider](app/Providers/AppServiceProvider.php)) — เว็บเซิร์ฟเวอร์ (Nginx/Apache/IIS) ต้องมีใบรับรอง https ให้พร้อม เพราะฟีเจอร์ที่ต้องใช้กล้อง/ตำแหน่ง (สแกน QR หน้าประตู, GPS ลงเวลาครู) และ LINE webhook ใช้งานได้เฉพาะบน https เท่านั้น
4. **แคชไว้ล่วงหน้า** (เร็วขึ้นมาก ปลอดภัยที่จะทำได้เพราะโค้ดไม่มีการอ่าน `env()` นอกไฟล์ `config/`):
   ```bash
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```
   ถ้าแก้ `.env` หลังจากนี้ ต้องรัน `php artisan config:clear` ก่อนค่าจะมีผล
5. **สำรองข้อมูลอัตโนมัติ**: `php artisan backup:database` (MySQL = mysqldump · SQLite = สำเนาไฟล์) และ `php artisan backup:files` (รูป สลิป ใบรับรองแพทย์ ภาพกระดาษคำตอบ ฯลฯ เป็น .zip) เก็บที่ `storage/app/backups` ย้อนหลัง 14 วัน (ปรับด้วย `--keep-days`) ตั้งเวลาไว้แล้วใน [routes/console.php](routes/console.php) ทุกคืน 02:00 และ 02:15 · ผู้ดูแลกด "สำรองตอนนี้" และดาวน์โหลดไฟล์สำรองได้ที่เมนู **สำรองข้อมูล** · **กู้คืน**: `php artisan backup:restore` (เลือกไฟล์จากรายการ ระบบสำรองข้อมูลปัจจุบันไว้ก่อนกู้เสมอ) — แต่ตัวกำหนดการจะทำงานก็ต่อเมื่อมีอะไรสักอย่างเรียก `php artisan schedule:run` ทุกนาที:
   - **Windows**: สร้าง Task ใน Task Scheduler ให้รัน `php artisan schedule:run` (working directory = โฟลเดอร์โปรเจกต์) ทุก 1 นาที
   - **Linux**: เพิ่ม cron `* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1`

   ควรคัดลอกไฟล์ในโฟลเดอร์ `storage/app/backups` ไปเก็บไว้นอกเครื่องเป็นระยะด้วย (ไดรฟ์อื่น/คลาวด์) เผื่อเครื่องเสีย
6. **สิทธิ์ไฟล์**: โฟลเดอร์ `storage/` และ `bootstrap/cache/` ต้องเขียนได้โดยเว็บเซิร์ฟเวอร์
7. **คิว/งานเบื้องหลัง**: ระบบยังไม่ได้ใช้คิวจริงจัง (การแจ้งเตือน LINE ใช้ `defer()` ทำงานหลังตอบ response ไม่ใช่คิว) จึงไม่จำเป็นต้องรัน `queue:work` แต่ถ้าจะรันไว้เผื่ออนาคตก็ทำได้ปลอดภัย

| **เบิกวัสดุ / คลังวัสดุ** (`/requisitions`, `/supplies`) | ครูเขียนใบเบิกหลายรายการ (เห็นคงคลัง) → งานพัสดุได้ LINE → จ่ายจริงปรับจำนวนได้ไม่เกินคงคลัง → **ตัดสต็อกอัตโนมัติ** แจ้งผู้เบิก · พิมพ์ใบเบิกพร้อมช่องลงนาม · รับเข้า / ปรับยอดตามการตรวจนับ · **บัญชีวัสดุ** (รับ-จ่าย-คงเหลือทุกรายการ) · เตือนวัสดุใกล้หมด · สรุปการจ่ายรายเดือนแยกรายการและกลุ่มสาระ/งาน · **รหัสวัสดุออกอัตโนมัติ**เมื่อเว้นว่าง (`/supplies/numbering` เช่น `{CAT}-{SEQ3}` → OF-001 ตั้งรหัสหมวดได้) · วัสดุแต่ละรายการมีรูป รหัส ราคาต่อหน่วย ที่เก็บ และรายละเอียด → รวมมูลค่าคงคลัง / มูลค่าใบเบิก · หน้าเขียนใบเบิกเป็นแคตตาล็อกรูปภาพ + ตะกร้าใบเบิก |
| **ตรวจสอบพัสดุประจำปี** (`/asset-checks`) | กรรมการเดินสแกน QR ทีละห้องด้วยมือถือ เลือกผล พบ / ชำรุด / ไม่พบ (หรือพิมพ์เลขครุภัณฑ์) · รายงานแยกห้อง พร้อมช่องลงนามคณะกรรมการ |

ผู้จัดการครุภัณฑ์และรับเรื่องแจ้งซ่อม = ผู้ดูแลระบบ + ครูที่เลือกใน **ตั้งค่า → งานพัสดุ / อาคารสถานที่** · ครูทั่วไปเห็นเฉพาะรายการที่ตัวเองแจ้ง และเห็นข้อมูลครุภัณฑ์แบบไม่มีราคาเมื่อสแกน QR

> **ต้องใช้ HTTPS** เมื่อนำขึ้นใช้งานจริง: กล้องสแกน QR และ GPS บนมือถือทำงานเฉพาะบน https (หรือ localhost) และ LINE webhook ต้องเป็น https ที่เข้าถึงได้จากอินเทอร์เน็ต

## ป้องกันข้อมูลหายและตรวจสอบย้อนหลัง

- **ลบรายวิชา** ได้เฉพาะรายวิชาที่ยังไม่มีคะแนน ผลการเรียน หรือการเช็คชื่อรายคาบ (เช่น เปิดผิดห้อง)
- **ลบนักเรียน** ได้เฉพาะคนที่ยังไม่มีคะแนน การมาเรียน ใบแจ้งหนี้ เอกสาร ปพ. หรือเงิน/รายการในกระเป๋าเงิน — คนที่ย้าย/ลาออกให้เปลี่ยนสถานะแทน ประวัติจะอยู่ครบสำหรับออก ปพ.1/ปพ.7
- **ลบบัญชีผู้ใช้** ไม่ได้ถ้ามีเงินหรือรายการในกระเป๋าเงิน เคยขายที่หน้าจอขาย หรือเคยทำรายการกระเป๋าเงิน/จ่ายเงินร้านค้า ให้ปิดใช้งานแทน · ฐานข้อมูลกันซ้ำอีกชั้น (FK แบบ restrict) สมุดรายการและยอดขายของร้านจึงไม่หายตามการลบ
- **ลบข้อมูลที่พ้นระยะเก็บ (PDPA)**: `php artisan privacy:purge` ตั้งเวลาไว้ทุกวันที่ 1 ของเดือน แต่ทำงานเฉพาะเมื่อเปิดสวิตช์ในหน้าตั้งค่า (ค่าเริ่มต้น = ปิด)
- **ปิดยอดรายวัน** รวมเงินสดของกระเป๋าเงิน: เงินสดที่ต้องนำส่ง = ค่าธรรมเนียมเงินสด + เติมเงินสด − ถอนคืนเงินสด − จ่ายร้านค้าเงินสด
- **ประวัติการแก้ไข** (`/audit` ผู้ดูแลระบบ): บันทึกอัตโนมัติว่าใคร ทำอะไร เมื่อไร จาก IP ไหน พร้อมค่าเดิม → ค่าใหม่ ครอบคลุม แก้คะแนนหลังล็อก · ผลพิเศษ/แก้ตัว · ตั้ง มส. · ลบช่องคะแนน · ล็อก/ปลดล็อกรายวิชา · แก้/ลบข้อมูลนักเรียน · อนุมัติการจบ · ออก ปพ.7 · ใช้แบบพิมพ์ ปพ.1 · รับชำระ/ยกเลิกใบแจ้งหนี้/ตรวจสลิป · แก้/ลบบัญชี รีเซ็ตรหัสผ่าน · ตั้งค่าโรงเรียน (ไม่เก็บค่า token) · เลื่อนชั้น · เปลี่ยนภาคเรียน · แก้หรือลบประวัติจากหน้าเว็บไม่ได้ · ดูประวัติของนักเรียนคนเดียวได้จากปุ่ม 🕘 ในหน้าข้อมูลนักเรียน

## รหัสผ่าน

- บัญชีที่ได้รหัสผ่านจากคนอื่น (ผู้ดูแลสร้าง/รีเซ็ตให้ · บัญชีผู้ปกครองที่สร้างอัตโนมัติจากการเพิ่มนักเรียน นำเข้า หรือมอบตัว · บัญชีนักเรียน) **ต้องตั้งรหัสใหม่เองตอนเข้าครั้งแรก** ก่อนใช้งานหน้าอื่น
- รหัสใหม่: อย่างน้อย 8 ตัว มีตัวอักษรและตัวเลข ห้ามใช้ชื่อผู้ใช้หรือเบอร์โทร
- **ลืมรหัสผ่าน** (ลิงก์ในหน้าเข้าสู่ระบบ): ส่งรหัสยืนยัน 6 หลักทาง LINE ที่เชื่อมไว้ ใช้ได้ 10 นาที ผิดได้ 5 ครั้ง · บัญชีที่ไม่ได้เชื่อม LINE ให้ครู/ผู้ดูแลรีเซ็ตให้
- เริ่มใช้กับบัญชีเดิมที่ยังใช้รหัสเริ่มต้น: `php artisan users:require-password-change --role=parent` (หรือ `--role=student`, เว้นว่าง = ทุกบัญชี)

### ยืนยันตัวตน 2 ขั้น (2FA)

- ครูและบุคลากรเปิดใช้เองที่ **ข้อมูลส่วนตัว → ยืนยันตัวตน 2 ขั้น** (`/two-factor`): สแกน QR ด้วย Google Authenticator / Microsoft Authenticator แล้วยืนยันรหัส 6 หลัก · ได้รหัสสำรอง 8 รหัส (แสดงครั้งเดียว ใช้ได้รหัสละครั้ง)
- เข้าสู่ระบบ: รหัสผ่าน (หรือ LINE) → รหัสจากแอป · ผิด 5 ครั้งล็อก 15 นาที · รหัสเดิมใช้ซ้ำไม่ได้ · กุญแจลับเก็บแบบเข้ารหัส รหัสสำรองเก็บเฉพาะค่าแฮช
- **บังคับใช้**: ตั้งค่า → ความปลอดภัยของบัญชี — ผู้ดูแลระบบและบุคลากรที่มีสิทธิ์ `finance.manage` `wallet.manage` `users.manage` `settings.manage` ต้องเปิดใช้ก่อนจึงเข้าหน้าอื่นได้ (ค่าเริ่มต้น = ไม่บังคับ)
- มือถือหาย: เข้าด้วยรหัสสำรอง · ไม่มีรหัสสำรอง ให้ผู้ดูแลกด "ล้างการยืนยันตัวตน 2 ขั้น" ในฟอร์มผู้ใช้ · ผู้ดูแลระบบเอง: `php artisan users:disable-2fa ชื่อผู้ใช้`
- เขียน TOTP (RFC 6238) เองใน [app/Support/Totp.php](app/Support/Totp.php) ไม่ได้เพิ่ม package

## บทบาทและสิทธิ์

- **ผู้ดูแลระบบ**: ทุกอย่าง รวมถึงการเงิน ผู้ใช้ ตั้งค่า
- **ครู**: เช็คชื่อ ใบลา ความประพฤติ ข้อมูลนักเรียน กรอกคะแนน*เฉพาะวิชาที่ตัวเองสอน* ประกาศถึงห้องที่ดูแล
- **ผู้ปกครอง**: เห็นเฉพาะข้อมูลบุตรหลานของตัวเอง ส่งใบลา
- **นักเรียน**: เห็นเฉพาะข้อมูลของตัวเอง ส่งการบ้าน เพิ่มผลงานลงแฟ้ม (รอครูรับรอง) แก้ชื่อเองไม่ได้
